# Motion + Guidelines mock: notes

**Design summary:** a light "airmail" portfolio on warm paper (#F3EFE3) with ink type, the logo's coral and a sage secondary. It pairs Fraunces display and Geist text, and uses postmark rings, cancellation waves, a dashed flight route and airmail-stripe borders in place of grids.

- **Motion gate and purpose (animate §1–2):** the staged hero entrance and scroll reveals are rare marketing moments. Hovers are near-imperceptible feedback (translateY of 3–4px, image scale of 1.025). The Flier demo serves to explain. Nothing animates on a frequent or keyboard action.
- **Curves and durations from the skill's tables only:** `--ease-out: cubic-bezier(0.23,1,0.32,1)` for entering, `--ease-in-out: cubic-bezier(0.77,0,0.175,1)` for the route and process line drawing, `ease` for colour changes, `linear` only for the spinner. Button presses use `scale(0.97)` at 160ms. UI transitions stay between 200 and 300ms. Marketing entrances run 600–800ms with a 60–70ms stagger. There is no `ease-in` and no `scale(0)`.
- **Compositor-only properties:** every animation uses `transform`, `opacity` or `clip-path` (the route, process line and progress bar use `scaleX`). Every transition lists its exact properties, with no `transition: all`. Inline SVG transforms use `transform-box: fill-box` with an explicit `transform-origin`.
- **Interruptible Flier mail-merge demo:** `{{name}}`, `{{city}}` and `{{email}}` swap via WAAPI as a 140ms exit, blur and up, then a 240ms enter. Any running animation is cancelled first, so rapid row clicks retarget cleanly. Rows are real `<button aria-pressed>` elements. The letter is `aria-live="polite"`. Autoplay runs only while the demo is in view and the tab is visible, and a Pause/Play button covers the guideline on autoplay longer than 5s.
- **`prefers-reduced-motion`:** this gives fewer and gentler motions, not none. Entrances become 200ms opacity fades, and the route and process lines appear drawn. Hover movement is removed while colour and shadow feedback stay. Token swaps become crossfades and the demo doesn’t autoplay (rows and the button still step through it).
- **Hover gating:** all `:hover` motion sits inside `@media (hover:hover) and (pointer:fine)`. `:active` press feedback stays ungated. `touch-action: manipulation` and the tap-highlight colour are set on purpose.
- **Accessibility:** the page has a skip link, a sticky header with `scroll-padding-top` so focused or anchored content isn't covered, and `:focus-visible` rings everywhere (inputs get a ring in place of the outline). Headings run in order, icon-only controls have `aria-label`, and decorative SVGs are `aria-hidden`. Links that open a new tab say so to screen readers.
- **Forms:** fields have labels, `autocomplete`, `name` and the correct `type`/`inputmode`. The email field has `spellcheck=false`. Placeholders end with "…". Errors appear inline with a next step, and the first invalid field gets focus. The submit button stays enabled until sending starts, then shows "Sending…" with a spinner. The page warns before leaving if the form has unsaved input. Copy feedback uses `aria-live`.
- **Content and performance rules:** every image has `width`/`height`, below-fold images use `loading="lazy"`, and the hero image uses `fetchpriority="high"`. The page uses `preconnect` for fonts, `text-wrap: balance`/`pretty`, curly quotes, `tabular-nums` on counters, `translate="no"` on brand names, and `Intl` for the IST clock, year and counts. FAQ panels deep-link through the URL hash. `theme-color` matches the page background. The native select has an explicit background colour and text colour.
- **Honest content:** there are no testimonials, logos or invented stats. The demo uses clearly labelled sample data. The unverified Tata Memorial line is one `<p data-removable>` with an HTML comment marking it for removal.
